# 03 — Classification of order-ten binary 3-frameproof codes

**Status: Complete computer-assisted proof, verified in Lean.** Project label: GPT-6 Astra. The mathematical proof was completed on 8 October 2026; this publication package was checked on 10 October 2026.

Every binary `SHF(10;10,2,{1,3})` is a permutation matrix up to independent complementation of its rows. Equivalently, every binary 3-frameproof code with ten coordinates and ten codewords has this trivial form. Guo, Stinson and van Trung explicitly left this order-ten question open in concluding problem 3 of [their 2015 paper](https://cs.uwaterloo.ca/~dstinson/papers/sdesign-5.pdf).

The final declarations are:

```lean
theorem GPT6Astra.every_order_ten_shf_is_trivial
    (A : BinaryMatrix 10) (h : IsSHF A) : IsTrivial A

theorem GPT6Astra.not_openProblem10 : ¬ OpenProblem10
```

`IsSHF` requires separation of each designated column from every triple of distinct other columns. `IsTrivial` asserts the existence of an actual permutation and independent row-complement bits. The theorem imposes no design, regularity, distinct-row, or additional weight hypothesis.

The proof reduces a hypothetical nontrivial matrix to one of four canonical cases, with first-row weight 2, 3, 4, or 5. Each case has 840 separation conditions, 80 row-order conditions, 63 column-order conditions, and 19 fixed-entry conditions. Lean proves that every counterexample yields these constraints and then checks their unsatisfiability using saved LRAT certificates.

## Reproduce

Install the toolchain selected by `gpt6_astra/lean-toolchain`, then run:

```bash
cd gpt6_astra
./lake exe cache get
./verify.sh
```

The wrapper uses an installed Lake when the optional local toolchain is absent. The project pins Lean 4.34.1 and mathlib commit `d13f23b723b8a846827a245b89c10fc7d3f11612`. The manifest locks the other dependencies. Do not update those pins to reproduce the recorded result.

`verify.sh` checks hashes and pins, builds the four cases sequentially, builds the final theorem, and freshly rechecks each case and the final theorem from source with warnings treated as errors. Sequential execution limits memory use. An up-to-date Lake cache alone is not counted as a fresh certificate check. See [the detailed instructions](gpt6_astra/README.txt).

## Verification trust

The completed theorem has no `sorryAx` dependency or user-written axiom asserting a combinatorial conclusion. Its dependency report contains `propext`, `Classical.choice`, `Quot.sound`, and four evaluation axioms generated by standard `bv_check`.

Those four dependencies matter: certificate checking uses Lean's compiled evaluator, so this proof trusts the compiler/runtime evaluation path in addition to the kernel and standard foundations. The paper and audit state this explicitly. The SAT solver's answer must pass certificate checking.

Four separately generated CNFs also have ordinary-kernel Lean proofs whose reported dependency is only `propext`. These are included as optional corroboration. They do not replace the integrated matrix proof or remove its compiled-checker dependencies.

## Novelty and publication scope

The public-source audit and focused recheck through 10 October 2026 found no earlier resolution of this exact classification. This supports a qualified novelty claim; it does not establish absolute priority. In particular, the full text of Sun and Wang's 2025 *New upper bounds for wide-sense frameproof codes* was inaccessible, so its complete theorem statements and possible consequences were not checked. The [prior-art review](reviews/prior-art-review.md) records that gap and the sources examined.
